# КлинВект — Администратор

Локальное Windows-приложение для загрузки выгрузок 1С, расчёта показателей врачей и отделений, административных комментариев и формирования PDF/Excel-отчётов.

Версия 2.6 добавляет рабочую мобильную версию для Битрикс24 Black Hole: Admin формирует один PIN-зашифрованный `.kvmobilebundle` сразу для всех активных врачей, а PWA открывает личный отчёт после входа в Битрикс24 и ввода постоянного PIN Viewer. Список пациентов и исходные выгрузки в мобильную публикацию не входят.

## Установка

Используйте только актуальный установщик:

[Скачать КлинВект Admin 2.6 для Windows](https://github.com/Klok1305/DoctorReview/releases/download/v2.6.1/KlinVekt-Shcherbatova-Admin-Setup-2.6.1-x64.exe)

Portable-версия не выпускается. Установщик создаёт ярлык «КлинВект — Администратор» и устанавливается в профиль текущего пользователя Windows. Устанавливать приложение нужно под той же индивидуальной учётной записью, которая будет его запускать.

Для врачей используется [отдельный установщик КлинВект Viewer 2.6](https://github.com/Klok1305/DoctorReview/releases/download/v2.6.1/KlinVekt-Shcherbatova-Viewer-Setup-2.6.1-x64.exe). Он создаёт обычный ярлык, не запускает службу и не требует SQL-сервера.

При первом запуске:

1. Выберите локальную рабочую папку, например `C:\ClinicData\PulseClinic-Test`.
2. Приложение откроется сразу, без логина и пароля.
3. Не выбирайте OneDrive, UNC, SMB или другой сетевой путь.
4. Не предоставляйте посторонним доступ к компьютеру и рабочей папке администратора.

Приложение создаст структуру:

```text
PulseClinic-Test
├── Входящие
├── База
│   └── оценка-врачей.sqlite
├── Результаты
├── Резервные копии
└── Журналы
```

Настройки путей находятся в `config.json` внутри папки данных приложения в `%APPDATA%`. После переименования приложение находит прежнюю конфигурацию `%APPDATA%\Пульс клиники — Администратор` или `%APPDATA%\Пульс клиники` и продолжает использовать выбранную рабочую папку. Viewer аналогично подхватывает `viewer-config.json` из прежней папки `%APPDATA%\Пульс клиники — Viewer`.

## Возможности администраторской версии

- импорт `.xls`, `.xlsx` и `.zip` с выгрузками 1С;
- расчёт метрик врачей, специализаций и отделений;
- административные комментарии к аналитическим блокам;
- PDF по выбранным врачам, специализациям и отделениям;
- сводная Excel-таблица;
- проверенные SQLite-копии и перенос всей базы файлом `.ovbackup`;
- восстановление с предварительной страховочной копией;
- ручные и автоматические обновления установленной версии.
- постоянные четырёхзначные PIN врачей и отдельный администраторский PIN Viewer;
- постоянное назначение заведующих отделениями с доступом к отчётам врачей своего отделения;
- формирование одного автономного HTML или проверяемого ZIP по выбранным периодам, врачам, отделениям и специализациям;
- включение административных комментариев в опубликованные страницы.
- формирование файла `.kvmobile` для мобильного отчёта выбранного врача без персонального списка пациентов и исходных выгрузок.
- формирование одного `.kvmobilebundle` для всех активных врачей с отдельным AES-256-GCM шифрованием каждого отчёта существующим PIN Viewer;
- серверная PWA для Bitrix24 Black Hole с проверкой учётной записи портала, административной загрузкой общего пакета и ограничением попыток PIN.

Администраторская программа не показывает экран входа и не запрашивает логин или пароль: доступ к ней ограничивается самим компьютером администратора. Врачи работают только в отдельном Viewer, который не открывает рабочую SQLite.

## Мобильная версия через Битрикс24

1. Разверните серверный пакет `KlinVekt-Mobile-Server-2.6.1.zip` из GitHub Release на Black Hole с Node.js и портом 3000.
2. В политике доступа Black Hole разрешите сотрудников портала (`PORTAL`), но не включайте публичный режим.
3. В Admin откройте «Настройки → Публикация в Viewer», нажмите «Включить всех» и сохраните постоянные PIN врачей.
4. После загрузки выгрузок 1С откройте вкладку «Специалист» и нажмите «Все врачи для сервера».
5. В мобильной PWA администратор нажимает маленькую кнопку «Обновить всех» и выбирает полученный `.kvmobilebundle`.
6. Врач открывает приложение из своей учётной записи Битрикс24, выбирает имя и вводит свой обычный четырёхзначный PIN.

Подробная схема развёртывания, обновления и локальной проверки описана в [инструкции мобильной версии](docs/МОБИЛЬНЫЙ_ПИЛОТ.md).

## Публикация для Viewer

1. В «Настройки → Публикация в Viewer» включите нужных работников и проверьте их постоянные четырёхзначные PIN.
2. В блоке «Заведующие отделениями» выберите заведующего для каждого нужного отделения. Его доступ к Viewer включится автоматически.
3. Задайте администраторский PIN Viewer длиной 6–12 цифр. Он используется для импорта ZIP и отдельного полного входа администратора в автономный HTML.
4. На странице «Настройки» в блоке «Экспорт и публикация» нажмите «Файл для Viewer» и выберите получателей и периоды. Личные отчёты, специализации и отделения уже отмечены по умолчанию.
5. Если среди получателей есть назначенный заведующий, программа автоматически добавит в его зашифрованный набор отчёты всех врачей соответствующего отделения.
6. Подтвердите администраторский PIN и нажмите «Один автономный HTML». Внутри файла будет отдельный зашифрованный вход администратора ко всем включённым отчётам. Заведующий увидит переключатели врачей своего отделения, отделения и специализаций, а обычный врач — только собственные страницы. В личном отчёте отдельно переключаются окна назначений и клиентской базы 12/24/36 месяцев; пациентская база сворачивается, а рейтинги площадок показаны без полей редактирования.

Если отчёты должны накапливаться в общей папке, вместо HTML нажмите «ZIP для установленного Viewer» и передайте архив администратору Viewer.

На компьютере с правом записи в хранилище Viewer администратор выбирает общую папку, открывает маленькую панель «Администратор», перетаскивает ZIP, проверяет состав и выбирает, какие периоды и врачи импортируются. Viewer хранит версии обычными файлами, проверяет SHA-256 и не требует постоянно работающего процесса.

Рекомендуемая схема общей папки:

```text
PulseClinic-Viewer
├── catalog.json
├── _viewer
│   └── admin.json
└── doctors
    └── <непрозрачный-id>
        ├── access.json
        ├── index.json
        └── releases
```

Viewer не проверяет Windows-учётку и не использует NTFS как способ входа. Врач выбирает своё имя и вводит четырёхзначный PIN; после пяти ошибок вход блокируется на 15 минут. Страницы отчётов хранятся зашифрованными AES-256-GCM, ключ формируется из PIN через scrypt.

## Проверка на компьютере клиники

Настоящие выгрузки допускается использовать только на управляемом компьютере клиники с BitLocker, антивирусом и индивидуальной учётной записью тестировщика. Рабочие данные не следует копировать в облачные каталоги, общедоступные папки или на личные устройства.

Перед переносом на сервер проверьте:

- импорт контрольных выгрузок;
- совпадение выбранных показателей с 1С;
- PDF/Excel;
- перезапуск приложения;
- создание и тестовое восстановление `.ovbackup`.

## Перенос на сервер

1. Завершите импорт и закройте все изменения на тестовом ПК.
2. Нажмите «Полная копия для переноса» и сохраните `.ovbackup`.
3. Запишите SHA-256 и перенесите файл через защищённый ресурс клиники или зашифрованный носитель.
4. Установите на сервере под выделенной RDP-учёткой [тот же КлинВект Admin 2.5.14](https://github.com/Klok1305/DoctorReview/releases/download/v2.5.14/KlinVekt-Shcherbatova-Admin-Setup-2.5.14-x64.exe).
5. Выберите новую локальную папку, например `C:\ClinicData\PulseClinic`.
6. Создайте временного администратора чистой установки и восстановите `.ovbackup`.
7. После восстановления войдите с административными данными из перенесённой базы.
8. Сверьте месяцы, врачей, импорты и контрольные показатели.
9. Создайте две проверенные серверные копии до удаления данных с тестового ПК.

Конфигурационные пути тестового компьютера не входят в `.ovbackup` и на сервер не переносятся.

SHA-256 показывается программой после создания копии. Его также можно повторно получить в PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "C:\путь\к\копии.ovbackup"
```

## Разработка и выпуск

Требуются Node.js 22+ и pnpm 11+.

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm run test:smoke
pnpm run test:pdf
pnpm run dist
pnpm run dist:viewer
```

В `dist` создаётся NSIS-установщик Admin, в `dist/viewer` — отдельный установщик Viewer, а `pnpm run build:mobile-server` готовит автономное содержимое Black Hole в `tmp/klinvekt-mobile-server`. GitHub Release упаковывает его в `KlinVekt-Mobile-Server-<версия>.zip`. Portable-сборок нет. Рабочие базы, выгрузки, отчёты, журналы, резервные копии и сертификаты запрещено добавлять в Git.
