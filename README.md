# Пульс клиники — Администратор

Локальное Windows-приложение для загрузки выгрузок 1С, расчёта показателей врачей и отделений, административных комментариев и формирования PDF/Excel-отчётов.

Версия 2.2.1 разделена на два независимых приложения. «Администратор» остаётся однопользовательской программой с локальной SQLite, а отдельный on-demand Viewer показывает врачам только сформированные ZIP-публикации. Рабочая SQLite, исходные выгрузки 1С и администраторская программа через SMB не запускаются.

## Установка

Используйте только установщик:

`DoctorReview-Admin-Setup-2.2.1-x64.exe`

Portable-версия не выпускается. Установщик создаёт ярлык «Пульс клиники — Администратор» и устанавливается в профиль текущего пользователя Windows. Устанавливать приложение нужно под той же индивидуальной учётной записью, которая будет его запускать.

Для врачей используется отдельный установщик `DoctorReview-Viewer-Setup-2.2.1-x64.exe`. Он создаёт обычный ярлык, не запускает службу и не требует SQL-сервера.

При первом запуске:

1. Выберите локальную рабочую папку, например `C:\ClinicData\PulseClinic-Test`.
2. Приложение откроется сразу, без логина и пароля.
3. Не выбирайте OneDrive, UNC, SMB или другой сетевой путь.
4. Не предоставляйте посторонним доступ к компьютеру и рабочей папке администратора.

Приложение создаст структуру:

```text
PulseClinic-Test
├── Входящие
├── База
│   └── оценка-врачей.sqlite
├── Результаты
├── Резервные копии
└── Журналы
```

Настройки путей находятся в `config.json` внутри `%APPDATA%\Пульс клиники — Администратор`. При обновлении с 2.0.2 приложение находит прежнюю конфигурацию `%APPDATA%\Пульс клиники` и продолжает использовать выбранную рабочую папку.

## Возможности администраторской версии

- импорт `.xls`, `.xlsx` и `.zip` с выгрузками 1С;
- расчёт метрик врачей, специализаций и отделений;
- административные комментарии к аналитическим блокам;
- PDF по выбранным врачам, специализациям и отделениям;
- сводная Excel-таблица;
- проверенные SQLite-копии и перенос всей базы файлом `.ovbackup`;
- восстановление с предварительной страховочной копией;
- ручные и автоматические обновления установленной версии.
- постоянные четырёхзначные PIN врачей и отдельный администраторский PIN Viewer;
- формирование проверяемого ZIP по выбранным периодам, врачам, отделениям и специализациям;
- включение административных комментариев в опубликованные страницы.

Администраторская программа не показывает экран входа и не запрашивает логин или пароль: доступ к ней ограничивается самим компьютером администратора. Врачи работают только в отдельном Viewer, который не открывает рабочую SQLite.

## Публикация для Viewer

1. В «Настройки → Публикация в Viewer» задайте администраторский PIN длиной 6–12 цифр.
2. Включите нужных врачей и проверьте их постоянные четырёхзначные PIN.
3. На странице «Отчёт» нажмите «ZIP для Viewer».
4. Выберите периоды, типы страниц и врачей. Комментарии руководителя войдут в соответствующие страницы.
5. Передайте ZIP администратору Viewer через защищённый ресурс клиники.

На компьютере с правом записи в хранилище Viewer администратор выбирает общую папку, открывает маленькую панель «Администратор», перетаскивает ZIP, проверяет состав и выбирает, какие периоды и врачи импортируются. Viewer хранит версии обычными файлами, проверяет SHA-256 и не требует постоянно работающего процесса.

Рекомендуемая схема общей папки:

```text
PulseClinic-Viewer
├── catalog.json
├── _viewer
│   └── admin.json
└── doctors
    └── <непрозрачный-id>
        ├── access.json
        ├── index.json
        └── releases
```

Viewer не проверяет Windows-учётку и не использует NTFS как способ входа. Врач выбирает своё имя и вводит четырёхзначный PIN; после пяти ошибок вход блокируется на 15 минут. Страницы отчётов хранятся зашифрованными AES-256-GCM, ключ формируется из PIN через scrypt.

## Проверка на компьютере клиники

Настоящие выгрузки допускается использовать только на управляемом компьютере клиники с BitLocker, антивирусом и индивидуальной учётной записью тестировщика. Рабочие данные не следует копировать в облачные каталоги, общедоступные папки или на личные устройства.

Перед переносом на сервер проверьте:

- импорт контрольных выгрузок;
- совпадение выбранных показателей с 1С;
- PDF/Excel;
- перезапуск приложения;
- создание и тестовое восстановление `.ovbackup`.

## Перенос на сервер

1. Завершите импорт и закройте все изменения на тестовом ПК.
2. Нажмите «Полная копия для переноса» и сохраните `.ovbackup`.
3. Запишите SHA-256 и перенесите файл через защищённый ресурс клиники или зашифрованный носитель.
4. Установите тот же `DoctorReview-Admin-Setup-2.2.1-x64.exe` на сервере под выделенной RDP-учёткой.
5. Выберите новую локальную папку, например `C:\ClinicData\PulseClinic`.
6. Создайте временного администратора чистой установки и восстановите `.ovbackup`.
7. После восстановления войдите с административными данными из перенесённой базы.
8. Сверьте месяцы, врачей, импорты и контрольные показатели.
9. Создайте две проверенные серверные копии до удаления данных с тестового ПК.

Конфигурационные пути тестового компьютера не входят в `.ovbackup` и на сервер не переносятся.

SHA-256 показывается программой после создания копии. Его также можно повторно получить в PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "C:\путь\к\копии.ovbackup"
```

## Разработка и выпуск

Требуются Node.js 22+ и pnpm 11+.

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm run test:smoke
pnpm run test:pdf
pnpm run dist
pnpm run dist:viewer
```

В `dist` создаётся NSIS-установщик Admin, а в `dist/viewer` — отдельный установщик Viewer. Portable-сборок нет. Рабочие базы, выгрузки, отчёты, журналы, резервные копии и сертификаты запрещено добавлять в Git.
