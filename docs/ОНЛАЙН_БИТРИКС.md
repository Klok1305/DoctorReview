# Онлайн-КлинВект в Битриксе

Admin 3.1.0 выгружает обезличенный JSON, который администратор вручную загружает в приложение Битрикса. Ключ API для этого не нужен.

## Выгрузка и загрузка

1. Откройте онлайн-КлинВект из своей учётной записи Битрикс24. Первый файл загружает администратор портала. В блоке «Загрузить обезличенный JSON» показан его числовой ID.
2. В Admin откройте «Настройки → Онлайн-КлинВект в Битрикс24». Укажите этот ID среди администраторов КлинВекта, а напротив врачей — их ID сотрудников Битрикса. Пустой ID означает отсутствие онлайн-доступа.
3. Заведующие отделений берутся из сохранённых назначений Viewer. Для заведующего специализацией включите флажок напротив его врача; область соответствует его специализации в структуре Admin.
4. Нажмите «Выгрузить обезличенный JSON». Файл содержит личные отчёты, сводки специализаций, отделений и клиники за все рассчитанные месяцы с «Выработкой», включая графики и текущие комментарии. Пропуски и пояснения неполных оценок сохраняются.
5. В приложении Битрикса раскройте «Загрузить обезличенный JSON», выберите файл и нажмите «Загрузить отчёты».
6. После загрузки сотрудники видят отчёты согласно назначенным правам. Обновление данных и прав требует новой выгрузки и загрузки файла.

Используйте именно кнопку «Выгрузить обезличенный JSON». Полная JSON-копия на вкладке «Данные» содержит рабочую базу и сервером отвергается.

Имена врачей остаются. ФИО, ID и отдельные строки пациентов, реестр, исходные XLS/Excel, рабочие месяцы базы и PIN в пакет не входят. Реестр отключён до построения страниц. Дополнительная проверка известных имён и непрозрачных идентификаторов пациентов останавливает экспорт при обнаружении в тексте. Комментарии должны оставаться без данных пациентов.

## Доступ

Вход выполняется через текущую учётную запись Битрикса без отдельного PIN. Привязка идёт по ID сотрудника.

| Роль | Доступ |
|---|---|
| Врач | Только собственные личные отчёты |
| Заведующий специализацией | Сводка своей специализации и собственные отчёты |
| Заведующий отделением | Отделение, его специализации, все врачи отделения и собственные отчёты |
| Администратор КлинВекта | Все страницы клиники со всеми опубликованными комментариями |

Роли складываются. Заведующий без личной «Выработки» сохраняет доступ к управляемой области. Роль администратора портала используется только для начальной загрузки: после неё медицинский доступ и загрузка определяются явными правами в публикации. Загружающий должен оставаться администратором в новом JSON; файл, исключающий его из администраторов, отклоняется с подсказкой ID.

Сервер проверяет права на каждую страницу и каждую порцию загрузки. Адрес чужого отчёта не открывает доступ. Пользователю выдаётся только разрешённый каталог.

## Сервер

Разверните пакет `KlinVekt-Mobile-Server-3.1.0.zip` на существующем сервере Вайбкода с Node.js ≥22, портом 3000 и командой `node server.cjs`. Сохраните прежнюю политику доступа `PORTAL`/`NAMED_USERS` и непубличный gateway. Укажите:

```text
KLINVEKT_CLOUD_PORTAL_ID=<внутренний UUID портала из gateway>
KLINVEKT_DATA_DIR=/opt/klinvekt-data
```

ID портала — внутренний UUID из `X-Vibe-Portal-Id`, а не домен. Заголовки доверяются только за защищённым gateway Вайбкода. Настроенный онлайн-режим открывается по `/` и `/mobile/`, даже до первой публикации. Прежняя PWA с PIN остаётся по `/mobile/index.html`.

Каталог данных должен сохраняться при обновлении и быть доступен сервисному пользователю на запись. Текущая публикация хранится в `publications.kvcloud` вместе с ID портала. Прежний `.kvmobilebundle` остаётся отдельным файлом. Не помещайте данные в публичную папку или Git.

Официальный контракт: [gateway и контекст пользователя](https://vibecode.bitrix24.tech/docs/infra/app-runtime).

## Проверка файла и сбои

Формат `klinvekt-cloud-publication` v1 содержит только метаданные врачей, права и очищенные HTML-страницы с SHA-256. Сервер отвергает неизвестные поля, пациентские блоки, опасный HTML, неверные области и хеши. Предел файла — 100 МиБ, одной страницы — чуть менее 4 МиБ. Каталог выдаётся порциями по 128 страниц.

Файл передаётся порциями по 512 КиБ с хешами, таймаутами и ограниченными повторами. При обрыве или отмене выберите тот же файл и повторите загрузку: полученные порции доступны 20 минут до перезапуска сервера. Только полностью проверенный файл атомарно заменяет прежние отчёты. Неверный файл или незавершённая загрузка сохраняют действующую публикацию.

Отчёты имеют `Cache-Control: no-store`; сервис-воркер кэширует только оболочку. Offline-просмотр серверных отчётов не реализован.

## Дополнительная отправка через API

В Admin дополнительный свёрнутый блок позволяет сохранить ID приложения и ключ внешнего API. Это отдельный способ, требующий включения External API и разрешённого ID ключа в `KLINVEKT_CLOUD_KEY_IDS` на сервере. Ключ хранится через Windows safeStorage отдельно от базы. Для ручного сценария этот блок заполнять не требуется.

## Проверки

Node-тесты проверяют роли, совмещение прав, начальную загрузку, сохранение администратора, межсайтовые запросы, неизвестные поля, повреждённый пакет, повторные порции, отзыв прав и сохранение после перезапуска. Electron smoke проверяет реальные снимки Admin, агрегаты, комментарии и отсутствие реестра. WebKit проверяет экран iPhone в эмуляции, iframe, каталог администратора, ручную загрузку JSON и отказ полной копии базы.

После подключения нужно проверить вход настоящими учётными записями врача, заведующих и администратора. Локальные тесты эмулируют gateway и не подтверждают настройку живого портала или работу на физических телефонах.
