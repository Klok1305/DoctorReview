# Мобильный пилот КлинВект

`mobile-pilot/` — устанавливаемый PWA с демонстрационными данными и ручной загрузкой агрегированных метрик из Admin. Персональный список пациентов и исходные выгрузки в мобильный файл не попадают.

Пилот пока **не подключён** к серверу, Viewer или Битрикс24 и не выполняет настоящую авторизацию врача. Файл `.kvmobile` не зашифрован: он содержит ФИО врача и его рабочие показатели, поэтому этот режим предназначен только для контролируемого локального пилота.

## Что можно проверить

- демо-вход в личный отчёт;
- три периода и шесть векторов КлинВект;
- все агрегированные показатели личной вкладки «Метрики»: пять верхних KPI и подробности В1–В6;
- окна клиентской базы 12/24/36 месяцев без фамилий и списка пациентов;
- динамику, цели и комментарий руководителя;
- адаптацию под телефон;
- установку на главный экран;
- повторное открытие интерфейса без сети после первого успешного запуска.

## Как загрузить выгрузки

Сами Excel-выгрузки открываются только в Admin — мобильная версия их не разбирает.

1. Загрузите выгрузки 1С в Admin обычным способом и дождитесь расчёта метрик.
2. Откройте вкладку **«Специалист»** и выберите нужного врача.
3. Нажмите **«В мобильную версию»**.
4. Сохраните созданный файл с расширением `.kvmobile`.
5. Откройте мобильный пилот и нажмите **«Загрузить файл из Admin»**.
6. Выберите сохранённый `.kvmobile` — имя врача, периоды, пять верхних KPI, В1–В6, динамика и цели заменят демо-данные.

Файл загружается только в память открытой страницы и не отправляется на сервер. После перезагрузки страницы его потребуется выбрать снова. Admin включает до шести последних рассчитанных месяцев выбранного врача.

## Запуск на компьютере

Из корня репозитория выполните:

```powershell
pnpm run start:mobile-pilot
```

Откройте `http://127.0.0.1:4173/`.

Для проверки интерфейса на телефоне в одной Wi-Fi-сети выполните:

```powershell
pnpm run start:mobile-pilot:lan
```

Команда напечатает адрес вида `http://192.168.1.20:4173/`. Откройте его на телефоне. Это подходит для просмотра интерфейса, но установка PWA и офлайн-режим на телефоне требуют HTTPS.

## Куда разместить пилот

Нужен любой статический веб-сервер с HTTPS. Подойдут корпоративный Nginx/IIS, внутренний веб-сервер с доверенным сертификатом или отдельный тестовый поддомен, например:

```text
https://mobile-pilot.company.ru/
```

На сервер загружается **содержимое** каталога `mobile-pilot/` с сохранением структуры:

```text
корень сайта
├─ index.html
├─ app.css
├─ app.js
├─ demo-data.js
├─ manifest.webmanifest
├─ service-worker.js
└─ icons/
   ├─ app-icon-192.png
   └─ app-icon-512.png
```

Сервер должен:

- отдавать сайт по HTTPS;
- отдавать `.webmanifest` с типом `application/manifest+json`;
- не кэшировать надолго `index.html`, `manifest.webmanifest` и `service-worker.js`;
- не переименовывать файлы и не добавлять авторизацию через HTML-форму поверх сайта.

Для Nginx достаточно обычного статического сайта и такого типа файла:

```nginx
location / {
    root /var/www/klinvekt-mobile-pilot;
    try_files $uri $uri/ /index.html;
}

types {
    application/manifest+json webmanifest;
}
```

Для IIS добавьте MIME-тип `.webmanifest` → `application/manifest+json`, привяжите HTTPS-сертификат и скопируйте файлы в физический путь сайта.

Не загружайте каталог на Битрикс24.Диск как набор файлов: Диск не заменяет веб-сервер для service worker и установки PWA. После размещения отправьте тестировщикам обычную HTTPS-ссылку в закрытый чат Битрикс24. Файлы `.kvmobile` не рассылайте через общий чат и не складывайте в публичную папку.

## Установка на телефон

### iPhone

1. Откройте ссылку в Safari.
2. Нажмите «Поделиться».
3. Выберите «На экран Домой».
4. Включите «Открывать как веб-приложение» и нажмите «Добавить».

### Android

1. Откройте ссылку в Chrome.
2. Откройте меню браузера.
3. Нажмите «Установить приложение» или «Добавить на главный экран».

## Обновление пилота

Замените файлы на сервере и измените номер кэша в `service-worker.js`, например `klinvekt-mobile-pilot-v4` → `klinvekt-mobile-pilot-v5`. После следующего открытия телефон получит новую версию.

## Что понадобится для второго этапа

Для постоянного рабочего использования потребуется отдельный серверный API, авторизация сотрудника через Битрикс24, сопоставление пользователя с врачом, шифрование публикаций, отзыв доступа и аудит. Текущий `.kvmobile` — ручной мост для проверки сценария и состава экрана, а не финальный канал доставки медицинских данных.
