# Мобильная версия КлинВект 2.6

Рабочая мобильная версия состоит из PWA `mobile-pilot/` и Node.js-сервера `mobile-server/` для Битрикс24 Black Hole. Врач входит в приложение своей учётной записью Битрикс24, выбирает имя и вводит постоянный четырёхзначный PIN Viewer. Один общий файл обновляет отчёты всех включённых врачей.

Мобильная публикация повторяет содержание личной страницы Viewer: до шести последних рассчитанных периодов, пять верхних KPI, полные агрегированные показатели В1–В6, окна анализа, подкатегории выручки, реальные цели и факты, таблицу динамики, выводы и комментарии к разделам. Вёрстка адаптирована для телефона. Единственное содержательное исключение — список пациентов: он, идентификаторы пациентов и исходные Excel-выгрузки в мобильную версию не входят.

## Что подготовлено

- кнопка Admin **«Все врачи для сервера»** создаёт один `.kvmobilebundle`;
- сохранённые комментарии и выводы из личных страниц Viewer автоматически входят в новый пакет; отдельной выгрузки комментариев не требуется;
- каждый отчёт внутри пакета отдельно зашифрован AES-256-GCM; существующий PIN открывает только ключи разрешённых этому получателю отчётов;
- заведующий видит собственный отчёт и отчёты врачей назначенных ему отделений; назначения переносятся из Admin вместе с пакетом;
- Black Hole подтверждает учётную запись сотрудника Битрикс24 до показа формы PIN;
- только администратор портала видит кнопку **«Обновить всех»** и может загрузить общий пакет;
- сервер не отдаёт общий зашифрованный файл врачам, ограничивает попытки PIN и создаёт HttpOnly-сессию;
- PWA устанавливается на главный экран iPhone или Android без магазина приложений;
- прежний локальный режим `.kvmobile` оставлен для контролируемой демонстрации без сервера.

### Группировки и графики

Карточки В1–В6 — кнопки. Нажмите **«Открыть показатели →»** на нужной карточке: ниже откроется соответствующий раздел. Выбранная карточка выделяется и показывает «Показатели открыты».

В начале открытого вектора есть **«↑ К векторам»** для возврата к выбору. На телефоне прокручивается отчёт, а меню «Метрики / Динамика / Цели» занимает отдельную строку снизу и не перекрывает показатели. Окно установки закрывается крестиком, кнопкой «Понятно» или нажатием на затемнённый фон. Если после обновления сервера остаётся старая вёрстка, перезагрузите страницу или закройте и снова откройте PWA. Для обновления только интерфейса повторная выгрузка из Admin не нужна.

В «Распределении выручки» нажмите на категорию: откроются её подкатегории. В «Деталях назначений» раскрывайте уровни исходного отчёта 1С до конкретной услуги или товара. Есть кнопки «Раскрыть всё» и «Свернуть всё»; итоги родительских строк уже включают вложенные позиции, суммировать их повторно не нужно.

В метриках доступны диаграммы структуры выручки, экспертных позиций (штуки и деньги), выполненных направлений, назначений/результатов по фокусам и групп клиентской базы. Во вкладке «Динамика» — выручка, пациенты/визиты, загрузка/конверсии, клиентская база, баллы векторов и зеркальная структура выручки по месяцам. Графики появляются при наличии соответствующих данных. Под каждым есть «Точные значения»; линейные графики позволяют выбрать отдельный показатель. Группы клиентской базы могут пересекаться, поэтому показаны полосами, а не секторами одного целого.

Чтобы получить эти блоки в рабочем приложении:

1. Обновите Admin и серверный пакет PWA. При повторном деплое сохраните каталог `data/`; настройки доступа и PIN менять не требуется.
2. В обновлённом Admin снова нажмите «Все врачи для сервера» и сохраните новый `.kvmobilebundle`.
3. В мобильном приложении нажмите «Обновить всех» и загрузите новый файл. Затем войдите по прежнему PIN.

Старые файлы остаются читаемыми. Уже сохранённые подкатегории выручки можно раскрыть и в старом файле; иерархия назначений до номенклатуры и числовые данные новых графиков появятся только после нового экспорта. Если сам исходный отчёт 1С не содержит группировки, показываются типы направлений и доступные позиции — отсутствующие уровни не придумываются.

Четырёхзначный PIN сам по себе короткий, поэтому рабочий `.kvmobilebundle` нельзя отправлять в общие чаты или выкладывать в публичный каталог. На Black Hole он хранится только на сервере, а перебор PIN ограничен.

## Один раз: развернуть сервер в Битрикс24

В GitHub Release скачайте `KlinVekt-Mobile-Server-2.6.4.zip`. Это автономный серверный пакет без Electron, базы клиники и выгрузок.

1. В Битрикс24 Вайбкод откройте **«Серверы Black Hole»** и выберите созданный сервер либо создайте новый.
2. Разверните содержимое ZIP как Node.js-приложение. Команда запуска — `npm start`, внутренний порт — `3000`.
3. Для нового сервера ограничьте доступ сотрудниками портала (`PORTAL`) либо выбранными пользователями (`NAMED_USERS`). Не используйте `PUBLIC`. При обновлении существующего сервера оставьте его текущую ограниченную политику доступа.
4. После успешного деплоя откройте выданный HTTPS-адрес вида `https://app-…vibecode.bitrix24.tech/mobile/`.
5. При необходимости опубликуйте этот адрес как приложение в каталоге вашего портала, чтобы врачи открывали его из Битрикс24.

Black Hole сам передаёт серверу защищённые заголовки с идентификатором, именем и ролью текущего пользователя. Код не просит и не хранит пароль от Битрикс24. Официальная документация: [начало работы](https://vibecode.bitrix24.tech/docs), [инфраструктура Black Hole](https://vibecode.bitrix24.tech/docs/infra).

Для самостоятельной сборки серверного пакета из репозитория выполните:

```powershell
pnpm run build:mobile-server
```

Готовое содержимое появится в `tmp/klinvekt-mobile-server/`. Внутри уже есть `package.json`, сервер, проверка мобильного формата и PWA-ресурсы.

## Каждый раз: обновить всех врачей одним файлом

1. Загрузите Excel/ZIP-выгрузки 1С в Admin обычным способом и дождитесь расчёта метрик.
2. Один раз проверьте «Настройки → Публикация в Viewer»: нажмите **«Включить всех»** и сохраните таблицу PIN в защищённом месте.
3. Откройте вкладку **«Специалист»** и нажмите **«Все врачи для сервера»**.
4. Сохраните `КлинВект-мобильные-отчёты-<дата>.kvmobilebundle`.
5. Откройте мобильную PWA под учётной записью администратора Битрикс24.
6. Нажмите маленькую кнопку **«Обновить всех»** справа сверху и выберите `.kvmobilebundle`.
7. Дождитесь сообщения **«Обновлено: N врачей»**. Большой пакет автоматически передаётся небольшими частями и проверяется по контрольной сумме; делить файл вручную не нужно.
8. После сообщения с числом врачей файл больше никому отправлять не нужно: все врачи увидят новые данные по прежней ссылке.

В пакет входят отчёты всех активных в настройках Viewer врачей, у которых есть хотя бы один период с персональной **«Выработкой»**, как в настольном отчёте. Общие записи, ручные оценки и комментарии без «Выработки» не создают личный отчёт; настоящая нулевая выработка сохраняется. Заведующий без собственного отчёта тоже получает доступ, если в пакете есть отчёты его отделения. Admin отдельно сообщает число учёток без личных показателей.

Если в старом списке остались технические учётки без отчётов, обновите Admin до **2.6.4+**, создайте новый общий файл и загрузите через **«Обновить всех»**. Обновление только сервера или повторная загрузка старого файла не пересчитывает его содержимое. В новом файле KPI и В5/В6 также содержат сравнения с прошлым календарным месяцем и средним с начала года; комментарии и цели переносятся, список пациентов — нет.

## Доступ заведующих к подчинённым

1. Обновите Admin и мобильный сервер до **2.6.3** или новее.
2. В Admin откройте **«Настройки → Публикация в Viewer → Заведующие отделениями»**. Проверьте, какие отделения закреплены за заведующим; его доступ Viewer должен быть активен. Если назначения уже верны, менять их не нужно.
3. Заново сформируйте **«Все врачи для сервера»** и загрузите новый `.kvmobilebundle` через **«Обновить всех»**.
4. Заведующий выбирает себя на входе и вводит **свой прежний PIN**. Вверху появится блок **«Отчёты отделения»** с выбором врача; кнопка **«Мой отчёт»** возвращает к собственным показателям.

PIN подчинённых не требуется. Доступны только врачи закреплённых отделений, чьи отчёты включены в пакет, с теми же комментариями и графиками. Если собственного отчёта нет, сразу открывается первый доступный отчёт подчинённого. Обычные врачи видят только свой отчёт.

Новый общий пакет имеет формат 2 и требует обновлённого сервера. Старые пакеты формата 1 продолжают открываться на новом сервере, но содержат только личный доступ: назначения заведующих появятся после нового экспорта. Изменения назначений или PIN вступают в силу в мобильной версии после повторной загрузки общего файла; она завершает все прежние сессии.

## Как входит врач

1. Врач открывает приложение внутри Битрикс24 или по его Black Hole HTTPS-ссылке.
2. Битрикс24 проверяет личную учётную запись.
3. Врач выбирает себя в списке и вводит привычный четырёхзначный PIN Viewer.
4. Открывается личный отчёт без списка пациентов.

После пяти неверных попыток вход временно блокируется. Обновление общего пакета завершает текущие мобильные сессии, поэтому после публикации врачу нужно снова ввести PIN.

## Локальная проверка

Статический демонстрационный режим:

```powershell
pnpm run start:mobile-pilot
```

Рабочий серверный режим с локальной тестовой ролью администратора:

```powershell
pnpm run start:mobile-server:local
```

Откройте `http://127.0.0.1:3000/mobile/`. Локальный режим разрешён только на `127.0.0.1`; при обычном запуске сервер отвергает запросы без удостоверяющих заголовков Black Hole.

## Хранение и резервирование

Сервер сохраняет только текущий `.kvmobilebundle` в каталоге `KLINVEKT_DATA_DIR` (по умолчанию `data/`; на действующем Black Hole — `/opt/klinvekt-data`). При обновлении сохраняйте этот каталог и `.env`. SQLite Admin, Excel, PDF, `.ovbackup` и отдельные `.kvmobile` туда не загружаются. Каталог данных, сами мобильные пакеты, секреты и серверные журналы запрещены правилами Git.

Если Black Hole-сервер пересоздаётся, после деплоя просто сформируйте новый общий пакет в Admin и загрузите его кнопкой **«Обновить всех»**.
