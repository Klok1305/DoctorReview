# Мобильная версия КлинВект 2.6

Рабочая мобильная версия состоит из PWA `mobile-pilot/` и Node.js-сервера `mobile-server/` для Битрикс24 Black Hole. Врач входит в приложение своей учётной записью Битрикс24, выбирает имя и вводит постоянный четырёхзначный PIN Viewer. Один общий файл обновляет отчёты всех включённых врачей.

Мобильная публикация повторяет содержание личной страницы Viewer: до шести последних рассчитанных периодов, пять верхних KPI, полные агрегированные показатели В1–В6, окна анализа, подкатегории выручки, реальные цели и факты, таблицу динамики, выводы и комментарии к разделам. Вёрстка адаптирована для телефона. Единственное содержательное исключение — список пациентов: он, идентификаторы пациентов и исходные Excel-выгрузки в мобильную версию не входят.

## Что подготовлено

- кнопка Admin **«Все врачи для сервера»** создаёт один `.kvmobilebundle`;
- сохранённые комментарии и выводы из личных страниц Viewer автоматически входят в новый пакет; отдельной выгрузки комментариев не требуется;
- каждый отчёт внутри пакета отдельно зашифрован AES-256-GCM ключом из существующего PIN врача;
- Black Hole подтверждает учётную запись сотрудника Битрикс24 до показа формы PIN;
- только администратор портала видит кнопку **«Обновить всех»** и может загрузить общий пакет;
- сервер не отдаёт общий зашифрованный файл врачам, ограничивает попытки PIN и создаёт HttpOnly-сессию;
- PWA устанавливается на главный экран iPhone или Android без магазина приложений;
- прежний локальный режим `.kvmobile` оставлен для контролируемой демонстрации без сервера.

Четырёхзначный PIN сам по себе короткий, поэтому рабочий `.kvmobilebundle` нельзя отправлять в общие чаты или выкладывать в публичный каталог. На Black Hole он хранится только на сервере, а перебор PIN ограничен.

## Один раз: развернуть сервер в Битрикс24

В GitHub Release скачайте `KlinVekt-Mobile-Server-2.6.1.zip`. Это автономный серверный пакет без Electron, базы клиники и выгрузок.

1. В Битрикс24 Вайбкод откройте **«Серверы Black Hole»** и выберите созданный сервер либо создайте новый.
2. Разверните содержимое ZIP как Node.js-приложение. Команда запуска — `npm start`, внутренний порт — `3000`.
3. В настройках доступа сервера выберите политику для сотрудников портала (`PORTAL`). Не используйте `PUBLIC`.
4. После успешного деплоя откройте выданный HTTPS-адрес вида `https://app-…vibecode.bitrix24.tech/mobile/`.
5. При необходимости опубликуйте этот адрес как приложение в каталоге вашего портала, чтобы врачи открывали его из Битрикс24.

Black Hole сам передаёт серверу защищённые заголовки с идентификатором, именем и ролью текущего пользователя. Код не просит и не хранит пароль от Битрикс24. Официальная документация: [начало работы](https://vibecode.bitrix24.tech/docs), [инфраструктура Black Hole](https://vibecode.bitrix24.tech/docs/infra).

Для самостоятельной сборки серверного пакета из репозитория выполните:

```powershell
pnpm run build:mobile-server
```

Готовое содержимое появится в `tmp/klinvekt-mobile-server/`. Внутри уже есть `package.json`, сервер, проверка мобильного формата и PWA-ресурсы.

## Каждый раз: обновить всех врачей одним файлом

1. Загрузите Excel/ZIP-выгрузки 1С в Admin обычным способом и дождитесь расчёта метрик.
2. Один раз проверьте «Настройки → Публикация в Viewer»: нажмите **«Включить всех»** и сохраните таблицу PIN в защищённом месте.
3. Откройте вкладку **«Специалист»** и нажмите **«Все врачи для сервера»**.
4. Сохраните `КлинВект-мобильные-отчёты-<дата>.kvmobilebundle`.
5. Откройте мобильную PWA под учётной записью администратора Битрикс24.
6. Нажмите маленькую кнопку **«Обновить всех»** справа сверху и выберите `.kvmobilebundle`.
7. Дождитесь сообщения **«Обновлено: N врачей»**. Большой пакет автоматически передаётся небольшими частями и проверяется по контрольной сумме; делить файл вручную не нужно.
8. После сообщения с числом врачей файл больше никому отправлять не нужно: все врачи увидят новые данные по прежней ссылке.

В пакет входят все активные в настройках Viewer врачи, у которых есть хотя бы один рассчитанный период. Врачи без данных пропускаются, и Admin сообщает их количество.

## Как входит врач

1. Врач открывает приложение внутри Битрикс24 или по его Black Hole HTTPS-ссылке.
2. Битрикс24 проверяет личную учётную запись.
3. Врач выбирает себя в списке и вводит привычный четырёхзначный PIN Viewer.
4. Открывается личный отчёт без списка пациентов.

После пяти неверных попыток вход временно блокируется. Обновление общего пакета завершает текущие мобильные сессии, поэтому после публикации врачу нужно снова ввести PIN.

## Локальная проверка

Статический демонстрационный режим:

```powershell
pnpm run start:mobile-pilot
```

Рабочий серверный режим с локальной тестовой ролью администратора:

```powershell
pnpm run start:mobile-server:local
```

Откройте `http://127.0.0.1:3000/mobile/`. Локальный режим разрешён только на `127.0.0.1`; при обычном запуске сервер отвергает запросы без удостоверяющих заголовков Black Hole.

## Хранение и резервирование

Сервер сохраняет только текущий `.kvmobilebundle` в каталоге `data/`. SQLite Admin, Excel, PDF, `.ovbackup` и отдельные `.kvmobile` туда не загружаются. Каталог `data/`, сами мобильные пакеты, секреты и серверные журналы запрещены правилами Git.

Если Black Hole-сервер пересоздаётся, после деплоя просто сформируйте новый общий пакет в Admin и загрузите его кнопкой **«Обновить всех»**.
