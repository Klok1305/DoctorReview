# Выпуск и обновление администраторской версии

## Версия 2.6.11

Диаграмма клиентской базы Admin использует точные выгрузки за 36 месяцев и четыре группы: активные лояльные, лояльные спящие, новые в риске и потерянные. Пациенты вне условий и с пересечением групп показаны отдельными числами под графиком, без произвольного распределения. В настройках «Новые в риске» добавлен выбор давности: в пределах указанного срока или более него. Для прежних профилей сохранено условие «более». Рабочие базы совместимы.

## Версия 2.6.10

Исправлена подсказка «Остальных» в диаграмме клиентской базы Admin: она показывает фактическое распределение по числу визитов и давности посещения. Недоступность одной группы больше не приписывается всем пациентам. Раскрытие списка по клику убрано. Расчёт численности и состава сегментов сохранён.

## Версия 2.6.9

В диаграмме клиентской базы Admin наведение на «Остальные» показывает причины попадания и количество пациентов. Клик открывает полный список за месяц выбранной полосы с причиной, числом визитов и давностью посещения. Рабочая база и форматы данных сохранены.

## Версия 2.6.8

В Admin в таблице врача «Показатели по месяцам» убрана строка «Визиты». Под количеством выполненных и проданных назначений по фокусам добавлена конверсия от назначенного количества, под количеством активных пациентов — доля от общей базы. При отсутствии знаменателя выводится прочерк. Остальные показатели и форматы данных сохранены.

## Версия 2.6.7

В Admin динамика клиентской базы показана горизонтальными полосами с накоплением: месяцы слева, численность внутри сегментов, итоговая база справа. Каждый пациент учитывается в полосе один раз; порядок распределения пересечений пояснён в интерфейсе. Карточки показателей сохраняют прежние определения групп. Поддержаны 12 месяцев и пропуски данных. Рабочая база и форматы публикаций не меняются.

## Версия 2.6.6

В Admin переработан Вектор 3: «Планы лечения и конверсия в реализацию» отделены от «Выполненных планов лечения и назначений в текущем месяце». Убраны повторные проценты в заголовках, фокусы выделены цветом. Детализация показывает конверсию каждой услуги, раскрывает всю иерархию и больше не обрезает старые списки до 40 позиций. Блок выполнения использует фактическую выработку от перенаправлений текущего месяца и не показывает конверсию назначений.

В выполненных направлениях обычные услуги объединены в одну категорию «Услуги». В настройках выбранного профиля → «Номенклатура» добавлены варианты «Учитывать», «Исключить» и «По общему правилу». Индивидуальная настройка сохраняется сразу для всех месяцев этого профиля и имеет приоритет над общим правилом. Она меняет учтённую выручку от перенаправлений и связанные показатели, но не собственную выручку, конверсию назначений или широту фокусов. Позиции появляются после импорта «Выработки»; инструкция по настройке добавлена в интерфейс.

Личная таблица динамики начинается с января и поддерживает 12 месяцев; первая колонка стала уже, доступна горизонтальная прокрутка. Клиентская база показана помесячными линиями за одинаковое выбранное окно: пересекающиеся группы не складываются, пропуски не заменяются нулями. Исправлена повторная строка «Косметология» в итогах отделения, средний балл в лидерборде выделен цветом.

Рабочие базы, PIN и ранее выпущенные пакеты совместимы. Новое поле индивидуального учёта необязательно; без него сохраняется прежний расчёт. Изменения видны после обновления Admin, повторный импорт для новых настроек не требуется. Если в сохранённых назначениях отсутствует иерархия 1С, её можно восстановить повторным импортом исходного отчёта, содержащего группы.

## Версия 2.6.5

Исправлен импорт «Загрузки расписания»: фактическое время работы с пациентом берётся из подколонки «Факт», а не из соседней «Нормы». Пустой факт остаётся пустым. Сохраняется поддержка старых шапок без разделения на норму и факт и выгрузок со сдвинутой колонкой продолжительности по графику.

Значения длительности с разделителем тысяч, например `1 234:56`, теперь сохраняют минуты. Это исправляет фактическое время и зависящие от него показатели. Загрузка по журналу записи по-прежнему рассчитывается из занятых заявками часов и продолжительности по графику.

После обновления повторно импортируйте исходную выгрузку «Загрузка расписания» и подтвердите замену данных за её период: ранее сохранённые значения не содержат исходной колонки «Факт» и не могут быть восстановлены автоматически. Период определяется по строке внутри отчёта 1С; если указан неверный год, сформируйте выгрузку за нужный период заново. Рабочие базы, PIN и форматы публикаций совместимы с предыдущей версией.

## Версия 2.6.4

Мобильный экспорт использует тот же отбор врачей и периодов, что Admin/Viewer: необходим персональный отчёт «Выработка». Технические учётки, для которых общие выгрузки создавали пустые показатели, больше не попадают в новый пакет. Настоящий отчёт с нулевой выручкой сохраняется, наличие комментария не обязательно. Заведующий без собственной выработки по-прежнему входит к отчётам своего отделения.

KPI и карточки В5/В6 получили сравнения с предыдущим календарным месяцем и средним с начала года. Пропуски месяцев не подменяются последним доступным отчётом; единицы изменений совпадают с десктопом. Комментарии, цели, графики и ограничения на пациентские данные сохранены. Также включены исправления компоновки и закрытия окна установки на iPhone.

После обновления Admin сформируйте **новый** файл через «Специалист → Все врачи для сервера» и загрузите его в мобильной версии через «Обновить всех». Старый файл не изменится от обновления сервера. PIN, рабочая база и политика доступа Black Hole не меняются.

Карточки векторов получили явную подпись «Открыть показатели» и стрелку; выбранный вектор выделен. Сохранено облегчённое начертание текста на графиках.

Мобильная версия раскрывает категории выручки и полную иерархию назначений 1С до номенклатуры. Итоги родительских групп включают вложенные позиции; предусмотрены команды «Раскрыть всё» и «Свернуть всё». Добавлены графики личного десктоп-отчёта: выручка, экспертные позиции, направления и фокусы, клиентская база, динамика показателей и баллы векторов. Под графиками доступны точные значения; пропуски данных не превращаются в нули.

После обновления Admin и сервера Black Hole сформируйте новый `.kvmobilebundle` кнопкой «Все врачи для сервера» и загрузите его через «Обновить всех». Старые файлы продолжают открываться, но не содержат новых числовых рядов и полной иерархии. Список пациентов по-прежнему исключён, PIN и доступы не меняются.

Smoke/PDF-smoke проходят скрыто. Обрыв консоли (`EPIPE`) больше не порождает повторяющиеся окна Electron; журнал и итог сохраняются в `tmp/`, реальные ошибки завершают тест с ненулевым кодом. Рабочий режим Admin этим изменением не затронут.

Старые мобильные пакеты версии 1 продолжают открываться с доступным в них набором данных.

## Версия 2.6

Версия 2.6 переводит мобильный пилот в рабочий серверный сценарий для Bitrix24 Black Hole. На вкладке «Специалист» Admin одной кнопкой формирует `.kvmobilebundle` сразу для всех активных врачей с рассчитанными периодами. Каждый личный отчёт внутри пакета отдельно шифруется AES-256-GCM ключом из уже назначенного четырёхзначного PIN Viewer; список пациентов и исходные выгрузки по-прежнему запрещены схемой формата.

Отдельный Node.js-сервер принимает пакет только от администратора портала, проверяет учётную запись сотрудника по защищённым заголовкам Black Hole, ограничивает перебор PIN и привязывает HttpOnly-сессию к пользователю Битрикс24. Врач выбирает имя и вводит прежний PIN, после чего видит личные KPI, В1–В6, динамику и цели. Обновление общего пакета сразу меняет данные для всех и отзывает прежние мобильные сессии.

GitHub Release дополнительно содержит автономный `KlinVekt-Mobile-Server-<версия>.zip` для Node.js-деплоя на порту 3000 без Electron, SQLite и данных клиники. Статический `.kvmobile` одного врача оставлен только как локальный демонстрационный режим.

## Версия 2.5.14

Версия 2.5.14 добавляет готовый мобильный пилот без магазинов приложений. На странице «Специалист» Admin формирует отдельный `.kvmobile` для выбранного врача: до шести последних периодов, пять верхних KPI, полные агрегированные расшифровки В1–В6, динамика и цели. Персональный список пациентов, их идентификаторы и исходные выгрузки в файл не включаются; формат повторно проверяется в desktop-процессе перед сохранением.

Мобильная PWA принимает `.kvmobile` кнопкой «Загрузить файл из Admin», меняет демо-профиль на выбранного врача и держит публикацию только в памяти открытой страницы. Сама оболочка устанавливается с HTTPS-ссылки на главный экран iPhone или Android. Серверной синхронизации и авторизации Битрикс24 в этой версии нет; `.kvmobile` не зашифрован и предназначен для контролируемого пилота.

## Версия 2.5.13

Версия 2.5.13 добавляет явный выбор состава публикации для заведующих отделениями. Режим по умолчанию включает только отмеченных врачей: заведующий получает личный отчёт, а также выбранные сводные своего отделения и своей специализации, без личных страниц коллег и других специализаций отделения. Изменение действует для новых автономных HTML и ZIP. Уже выпущенные файлы не меняются и продолжают открываться с прежним составом и правами.

## Версия 2.5.12

Версия 2.5.12 упорядочивает навигацию по доступным отчётам в автономном HTML и установленном Viewer. Личный отчёт остаётся отдельной кнопкой, а каждое отделение выводится собственной строкой: слева находится отчёт отделения, справа — опубликованные специализации этого отделения. На узких экранах оба блока складываются вертикально без горизонтального обрезания.

Изменение касается только представления навигации. Набор опубликованных отчётов, PIN-защита и права врача, заведующего или администратора не меняются; если соответствующая страница не включена в публикацию, Viewer показывает понятное сообщение об её отсутствии.

## Версия 2.5.11

Версия 2.5.11 добавляет отдельный администраторский вход в автономный HTML. Администратор может открыть полный каталог врачей, периодов, отделений и специализаций, которые были реально включены в файл при экспорте. Состав публикации по-прежнему определяется выбранными периодами и типами страниц: административный вход не добавляет отсутствующие отчёты.

Для создания автономного HTML требуется подтвердить текущий администраторский PIN Viewer. PIN проверяется по сохранённому scrypt-хэшу SQLite, используется только в памяти и не записывается в файл открытым текстом. Полный каталог шифруется отдельным AES-256-GCM payload с ключом PBKDF2; врачебные и заведующие входы остаются независимыми и ограниченными своими разрешениями. Автономные HTML прежнего формата 2 продолжают открываться.

## Версия 2.5.10

Версия 2.5.10 расширяет отчёты заведующих в автономном HTML и установленном Viewer. После входа заведующий может независимо открыть личный отчёт любого доступного врача, общий отчёт отделения или отчёт одной из опубликованных специализаций. Личные страницы, специализации и отделения теперь включены в стандартную публикацию по умолчанию.

В личном отчёте можно переключать доступные окна Вектора 3 и точные окна клиентской базы 12, 24 и 36 месяцев. Реестр пациентов сворачивается, явно показывает месяц отчёта и период исходной выгрузки, поддерживает поиск и фильтры. В рейтингах сохраняются только статичные значения по площадкам; поля ручного ввода и кнопка сохранения в HTML не публикуются.

Полная переносимая JSON-копия теперь содержит не только аналитический снимок, но и источники, историю импортов и экспортов, комментарии со всеми версиями, публикации, настройки Viewer, действующие PIN и фактические назначения заведующих. Импорт такой копии предварительно создаёт страховочную SQLite-копию и откатывается к ней при ошибке. Старые JSON по-прежнему поддерживаются в режиме импорта аналитического снимка.

## Версия 2.5.9

Версия 2.5.9 добавляет в личный HTML-отчёт врача раздел «Пациенты для работы». В него входят все пациенты выбранного периода клиентской базы: ФИО, ID, сегменты, количество визитов, давность последнего визита и историческая выручка. Врач может искать пациента по ФИО или ID и фильтровать таблицу по сегментам, включая объединённую группу «Для работы».

Персональные строки добавляются только в личные страницы врачей и остаются внутри PIN-зашифрованной части автономного HTML или Viewer-пакета. В открытой части файла, а также в страницах отделений и специализаций ФИО и ID пациентов не публикуются. Заведующий видит реестры врачей своего отделения в соответствии с уже настроенными правами Viewer.

Версия 2.5.8 переводит настольную выгрузку отчётов в PDF на прямую печать подготовленной HTML-страницы через Chromium. Длинные таблицы, графики и смысловые блоки больше не уменьшаются до узкой полосы по центру листа; отчёт сохраняет полную ширину и разбивается на читаемые страницы A4. Для браузерной выгрузки также улучшено разбиение длинных изображений по светлым горизонтальным промежуткам.

В автономном HTML и установленном Viewer исправлена ширина поля выбора врача: список теперь помещается в карточку входа и не обрезается на узких окнах.

Версия 2.5.7 исправляет расчёт собственной записи в 1С для врачей, которых нет в уже загруженном общем отчёте за месяц. Отсутствие строки врача теперь считается фактическим нулём и участвует в оценке; отсутствие самого отчёта по-прежнему отображается как отсутствие данных. Исправление применяется и к ранее загруженным отчётам, в которых присутствуют другие врачи.

Версия 2.5.6 учитывает конверсию назначений выше 100% в междисциплинарном блоке. Если количество выполненных и проданных позиций превышает количество назначений, фактическая конверсия больше не отбрасывается как ошибка: она отображается в карточке, деталях и сводных данных, участвует в сравнении с целью и даёт полный балл Вектора 3 при её выполнении. Итоговый балл по-прежнему ограничен 100.

В настройках отделения и специализации появился отдельный блок «Правила учёта выручки от перенаправлений». Доступны режимы «учитывать все», «только внешние услуги» и ручная настройка. Можно независимо включать приёмы, анализы и товары, учитывать или исключать услуги без подразделения, а также выбирать подразделения, чьи услуги не должны увеличивать итоговую выручку. Специализация может наследовать правило своего отделения.

Группы из отчёта «Назначения» теперь можно целиком привязать к подразделению. Точная настройка кода или названия номенклатуры имеет приоритет, затем применяется самая глубокая привязанная группа 1С, после неё — резервная привязка фокуса. В отчёте показываются две суммы: все выполненные направления и сумма, фактически учтённая в выручке. Исключённые позиции остаются видимыми и получают отметку «не учитывается».

Для отделения «Физиотерапия» и специализации «Эстетисты» при первом обновлении автоматически включается режим внешних перенаправлений: приёмы, анализы и товары учитываются, услуги подразделений «Физиотерапия» и «Косметология» не учитываются, услуги остальных подразделений учитываются, а позиции без определённого подразделения ожидают настройки.

Версия также включает выгрузку всех сохранённых PIN врачей в Excel-таблицу с колонками «Врач» и «PIN». PIN записываются как текст и сохраняют ведущие нули. Файл содержит данные доступа, поэтому его следует хранить только в защищённой папке клиники.

Версия также включает исправленное междисциплинарное распределение выполненных направлений. Домашнее подразделение берётся из настройки конкретной номенклатуры; эта точная настройка имеет приоритет над резервной привязкой фокуса. Товары, приёмы и анализы всегда остаются самостоятельными категориями, а остальные услуги делятся на «Профильные услуги» и «Другие услуги клиники».

В структуру клиники добавлено отделение «Кардиология и Функциональная диагностика» со специализациями «Кардиология» и «Функциональная диагностика». Пан Константин Александрович назначается заведующим; Провоторова/Провторова и Ахильгова относятся к кардиологии, Перцхелия — к функциональной диагностике. При обновлении прежние профили «Кардиология» и «УЗИ» мигрируют без потери настроек.

В сводной таблице междисциплинарного подхода колонки «Выполнено» и «Продано» объединены в показатель «Выполнено + продано».

Роль работает и в автономном HTML, и в ZIP для установленного Viewer. Отчёты каждого получателя шифруются его собственным PIN. Если заведующий выбран среди получателей публикации, страницы врачей его отделения добавляются автоматически, даже если отдельным врачам вход в Viewer не включён.

Рабочие каталоги OneDrive и сетевые пути SMB/UNC отклоняются. Для тестирования и серверной эксплуатации следует выбирать локальный диск.

## Совместимость с 2.2.3, 2.2.1, 2.1.0 и 2.0.2

- При обновлении используется прежний `config.json` из `%APPDATA%\Пульс клиники — Администратор` или `%APPDATA%\Пульс клиники`, если новая папка настроек ещё не создана.
- Существующая SQLite-база мигрирует без удаления старых пользователей, комментариев и публикаций.
- Старые учётные записи сохраняются внутри SQLite для совместимости резервных копий и авторства комментариев, но для входа больше не используются.
- Копии `.ovbackup` старых версий можно восстановить штатной командой.
- Установленный Viewer 2.3.0 продолжает импортировать ZIP прежнего формата 2.2.x.
- Новый ZIP с ролью заведующего требует Viewer 2.3.0. Автономный HTML содержит нужный Viewer внутри и установки не требует.
- Назначения заведующих входят в SQLite и полные копии `.ovbackup`.
- Перед обновлением обязательно создаётся проверенная `.ovbackup`.

## GitHub Releases

1. Убедитесь, что `version` в `package.json` равна `2.6.11`.
2. Закоммитьте проверенные изменения в `main`.
3. Создайте тег той же версии:

   ```powershell
   git tag -a v2.6.11 -m "KlinVekt 2.6.11 — Admin four client groups"
   git push --atomic origin main v2.6.11
   ```

4. После успешного push сразу сообщите, что релиз запущен, и дайте ссылку https://github.com/Klok1305/DoctorReview/releases. Не ждите завершения сборки или публикации и не запускайте мониторинг без отдельной просьбы.

5. Workflow проверит репозиторий, запустит тесты, соберёт NSIS и мобильный ZIP, затем опубликует все перечисленные артефакты.

Установленная версия получает обновления из GitHub Releases. Перед установкой приложение создаёт резервную SQLite-копию. Рабочая база находится вне каталога программы и обновлением не заменяется.

## Ручное обновление

В приложении нажмите «Установить обновление из файла», выберите новый `KlinVekt-Shcherbatova-Admin-Setup-<версия>-x64.exe` и дождитесь создания страховочной копии. После обновления проверьте версию, немедленное открытие без логина, рабочие пути и контрольные показатели.

## Подпись Windows

Без сертификата Windows SmartScreen может показать предупреждение. Для подписанной сборки используются секреты `WIN_CSC_LINK` и `WIN_CSC_KEY_PASSWORD`; файл сертификата запрещено добавлять в Git.
