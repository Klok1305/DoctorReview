# Выпуск и обновление администраторской версии

## Версия 2.2.3

Версия 2.2.3 исправляет кнопку «Файл для Viewer»: в версии 2.2.2 окно публикации не открывалось из-за ошибки в имени функции сортировки месяцев. Автономная публикация одним HTML-файлом снова доступна. Такой файл можно передать врачу напрямую и открыть локально в актуальном браузере без установки и интернета. Содержимое отчётов зашифровано AES-256-GCM и расшифровывается только после ввода постоянного PIN врача. Прежний ZIP остаётся для установленного Viewer, общей папки и накопления публикаций.

В административном приложении кнопка «ZIP для Viewer» заменена на «Файл для Viewer». В окне публикации доступны «Один автономный HTML» и «ZIP для установленного Viewer». Администраторский PIN требуется только для ZIP; автономный HTML можно сформировать после включения врачей и проверки их PIN.

Рабочие каталоги OneDrive и сетевые пути SMB/UNC отклоняются. Для тестирования и серверной эксплуатации следует выбирать локальный диск.

## Совместимость с 2.2.1, 2.1.0 и 2.0.2

- При обновлении используется прежний `config.json` из `%APPDATA%\Пульс клиники`, если новая папка настроек ещё не создана.
- Существующая SQLite-база мигрирует без удаления старых пользователей, комментариев и публикаций.
- Старые учётные записи сохраняются внутри SQLite для совместимости резервных копий и авторства комментариев, но для входа больше не используются.
- Копии `.ovbackup` старых версий можно восстановить штатной командой.
- ZIP формата 2.2.1 продолжает поддерживаться установленным Viewer 2.2.3.
- Автономный HTML доступен в администраторской версии 2.2.3; исправлена неработавшая кнопка из 2.2.2.
- Перед обновлением обязательно создаётся проверенная `.ovbackup`.


В GitHub Release 2.2.3 публикуются файлы Admin и отдельный установщик Viewer:

- `DoctorReview-Admin-Setup-2.2.3-x64.exe`;
- `DoctorReview-Admin-Setup-2.2.3-x64.exe.blockmap`;
- `latest.yml` для автообновления только Admin;
- `DoctorReview-Viewer-Setup-2.2.3-x64.exe` без автообновления.

Portable-версия больше не собирается и не публикуется.

## GitHub Releases

1. Убедитесь, что `version` в `package.json` равна `2.2.3`.
2. Закоммитьте проверенные изменения в `main`.
3. Создайте тег той же версии:

   ```powershell
   git tag -a v2.2.3 -m "DoctorReview Admin + Viewer 2.2.3"
   git push origin v2.2.3
   ```

4. Workflow проверит репозиторий, запустит тесты, соберёт NSIS и опубликует установщик, `.blockmap` и `latest.yml`.

Установленная версия получает обновления из GitHub Releases. Перед установкой приложение создаёт резервную SQLite-копию. Рабочая база находится вне каталога программы и обновлением не заменяется.

## Ручное обновление

В приложении нажмите «Установить обновление из файла», выберите новый `DoctorReview-Admin-Setup-<версия>-x64.exe` и дождитесь создания страховочной копии. После обновления проверьте версию, немедленное открытие без логина, рабочие пути и контрольные показатели.

## Подпись Windows

Без сертификата Windows SmartScreen может показать предупреждение. Для подписанной сборки используются секреты `WIN_CSC_LINK` и `WIN_CSC_KEY_PASSWORD`; файл сертификата запрещено добавлять в Git.
