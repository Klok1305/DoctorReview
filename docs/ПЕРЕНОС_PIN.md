# Единые PIN в двух Admin и онлайн-КлинВекте

Подготовлено в исходниках 2026-10-09. Для использования обе установки Admin и онлайн-сервер должны получить согласованное обновление. Действующий сервер v5 пока не обновлён этим изменением.

## Первый перенос

1. Выберите Admin с правильными, уже выданными врачам PIN. Обычно это компьютер сотрудника, который общается с клиникой.
2. Откройте **Настройки → PIN врачей и публикация в Viewer → Перенос и синхронизация PIN**.
3. Введите пароль файла длиной 8–128 символов. При необходимости отметьте «Добавить администраторский PIN». Нажмите **«Сохранить PIN для другого Admin»**, сохраните `.kvpins` и передайте его второму сотруднику. Пароль передайте отдельно.
4. Во втором Admin откройте тот же раздел, введите пароль и нажмите **«Открыть файл PIN и сравнить»**.
5. Проверьте таблицу. Приложение предлагает общую привязку, ID вместе с ФИО или ФИО/структуру. Разные ID допустимы; неоднозначные совпадения выбираются вручную. «Пропустить» оставляет врача без изменения; один местный врач не может быть выбран дважды.
6. При первом переносе отметьте **«Использовать файл как общий набор PIN»**. Администраторский PIN меняется только при отдельном выборе **«Также заменить администраторский PIN»**.
7. Нажмите **«Применить выбранные PIN»**. Сравните идентификатор набора и версию в двух Admin. Ведущие нули сохраняются, например `0123`.

Отчёты, комментарии, флаги публикации, назначения заведующих и пути сохраняются. Только PIN и проверочные записи меняются одной транзакцией, с резервным сохранением прежних доступов внутри SQLite. «Откатить последний перенос» возвращает их, сохраняя текущие роли и данные, и создаёт новый набор для явной синхронизации. Если врач удалён или PIN нового врача конфликтует с восстановлением, откат останавливается.

При неполном сопоставлении Admin показывает частичный перенос и блокирует дальнейший экспорт набора PIN и полную онлайн-выгрузку. Завершите сопоставление исходного файла или отмените перенос. Различающийся состав врачей сначала приведите к согласованному составу: импорт PIN сам не создаёт карточки.

## Обновление только PIN онлайн

1. В синхронизированном Admin нажмите **«Выгрузить PIN для онлайн»**. Пароль не нужен: JSON содержит salted scrypt-верификаторы и сведения о врачах, без открытых PIN, пациентов и отчётов. Храните его как файл доступа и передавайте только ответственному администратору.
2. Онлайн откройте **«Обновить отчёты или PIN → Обновить только PIN»**. Загрузку выполняет администратор портала или вошедший администратор КлинВекта.
3. Выберите JSON, нажмите **«Сравнить PIN»**, проверьте всех врачей онлайн. При первом выборе подтвердите общий набор. Администраторский PIN можно перенести отдельно, если он включён в файл.
4. Нажмите **«Применить PIN»**. Страницы, их идентификаторы, комментарии и роли сохранятся. После изменения войдите снова: прежние сессии отзываются.

Все существующие врачи онлайн должны быть сопоставлены; лишние врачи файла могут быть явно пропущены. Нужна предварительная публикация с PIN (v2/v3). Начальная публикация и прежний v1 обновляются обычной полной выгрузкой из Admin.

## Последующие изменения

Меняйте общий набор в одном ответственном Admin и распространяйте новую версию тем же способом. Это ручная синхронизация файлами, без постоянной связи между компьютерами. Изменение PIN врача, администраторского PIN или состава набора повышает ревизию; изменение комментариев и ролей её не повышает.

Старая ревизия того же набора отвергается. Другой набор или конфликт одинаковых ревизий требуют явного выбора источника. После синхронизации сервер отвергает также старую полную публикацию и JSON без версии PIN, чтобы отчёты другого компьютера не вернули прежние коды. При отказе сначала синхронизируйте Admin, затем выгрузите отчёты заново.

Уже выданные HTML, ZIP Viewer и мобильные пакеты содержат прежний снимок доступов: для них создайте новую обычную публикацию. Полная JSON-копия сохраняет общую привязку PIN. Старые копии читаются, но без этой привязки потребуется новое явное согласование.

Технические границы: `.kvpins` v1 использует AES-256-GCM и scrypt, проверяется в worker с двумя одновременными проверками PIN. Сравнение действует 20 минут и привязано к окну Admin или сотруднику/порталу онлайн, а также текущим доступам/публикации. Сервер резервирует проверочные записи и сохраняет новый файл атомарно; при ошибке прежняя публикация и сессии остаются рабочими. Форматы SQLite 5 и снимка 4 не изменены.
