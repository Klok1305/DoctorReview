# Ускорение отчётов: Admin, онлайн и автономный HTML

Реализовано в исходниках 2026-10-09. Версия остаётся **3.1.2**; новый релиз и развёртывание сервера не запускались.

## Изменения

- **Admin:** расчёты выбранного врача, его календарной истории и сводных отчётов выполняются в Web Worker. Для врача передаются только его данные и общие профили/справочник; месяцы копируются отдельными сообщениями с возвратом управления окну. Сводки сохраняют полный состав врачей. При смене врача, месяца, вкладки или ревизии устаревший результат не применяется. Готовые результаты попадают в прежние ограниченные кэши; комментарии не сбрасывают расчёты.
- **Графики Admin:** создаются при появлении на экране, включая открытие свёрнутого раздела. Копирование PNG и PDF/Viewer принудительно подготавливают нужные графики. Экспорт раскрывает разделы для снимка, сохраняя пользовательские настройки сворачивания.
- **Автономный HTML v4:** после проверки PIN расшифровывается каталог доступа, затем только выбранная общая страница. Повторные открытия используют память текущего сеанса: до шести страниц и 12 МиБ. Быстрое переключение и выход отменяют применение устаревшей страницы. Изображения графиков загружаются по мере просмотра; кнопка печати сначала дожидается их декодирования. HTML v2/v3 по-прежнему читаются, но их единый зашифрованный payload нужно раскрыть полностью.
- **Онлайн:** SVG строится в браузере при появлении графика на экране; точные значения и исходные числовые серии передаются сразу. Перед печатью строятся все графики и раскрываются разделы. Сервер повторно использует до восьми готовых страниц, максимум 16 МиБ; права проверяются перед каждой выдачей. Новая публикация или обновление PIN очищает кэш. Отчёты не добавлены в постоянное браузерное хранилище.
- **PWA и онлайн:** повторно используют два форматтера чисел вместо создания `Intl.NumberFormat` для каждого значения. Текст чисел и координаты SVG совпадают с прежними.

Пациентские списки исторических и сводных расчётов не копируются из worker целиком: при запросе подробностей восстанавливаются ленивые совместимые getters. Формулы, полнота данных, комментарии, цели, PIN и параметры шифрования не изменены. Схемы SQLite и форматы публикаций не менялись.

## Проверки и замеры

`pnpm test --test-concurrency=1`: **213/213**. Новые числовые регрессии сравнивают worker с прямыми расчётами: полный/неполный состав, пропущенный февраль, изменение нормативов, пациентские списки, старые признаки импорта. Проверены отзывчивость вызывающего потока, отбрасывание старых ответов и ограничения кэшей.

Electron smoke прошёл при 1440 и 1040 px, с явной проверкой настоящего Web Worker. PDF smoke прошёл также с предварительно свёрнутыми разделами, без изменения сохранённых настроек просмотра. WebKit проверил PWA, онлайн на ПК/iPhone/iframe, числовые ряды и печать, автономный HTML на ПК/iPhone, быстрое переключение, повторное открытие и выход. Снимки графика телефона и карточек Admin просмотрены.

Воспроизводимый сценарий: `pnpm run benchmark:reports`; с HTML в браузере — `node scripts/benchmark-reports.cjs --webkit`. Результат сохраняется в `tmp/report-performance-benchmark.json`. Для сравнения прежнего форматирования можно задать `KLINVEKT_BENCHMARK_CHARTS_SOURCE` на сохранённый исходник `report-charts.js`.

На этой машине, синтетический набор **10 врачей × 12 месяцев × 500 пациентов в каждом окне**:

| Измерение | Прежде | После |
|---|---:|---:|
| Максимальная пауза основного JS-потока при расчёте сводки | 862 мс | 20 мс |
| Полное время расчёта с передачей данных | 857 мс | 994 мс |
| Построение 24 SVG-графиков с числовыми таблицами | 60 мс | 3,1 мс |
| Размер 24 готовых графиков / выбранной страницы с отложенными графиками | 350 КБ | 62 КБ |
| Расшифрование и gzip 12 HTML-страниц / одной выбранной, без общей проверки PIN | 25,4 мс | 2,1 мс |

Повторная серверная выдача из кэша заняла около 0,004 мс, повторное чтение расшифрованной HTML-страницы — около 0,005 мс; сетевой обмен и DOM сюда не входят. Перенос в worker сохраняет отзывчивость окна, добавляя расходы на передачу данных. Эти значения характеризуют синтетический сценарий, а не гарантированную скорость рабочей базы клиники.

## Как получить ускорение в рабочих приложениях

После согласованного выпуска обновить обе установки Admin и сервер онлайн. Автономные HTML нужно сформировать заново: прежний самодостаточный файл содержит прежний JavaScript. Для онлайн v3 новые числовые публикации не обязательны: сервер использует уже сохранённые отчёты. Старые онлайн HTML v1/v2 сохраняют совместимость и получают ленивую загрузку изображений.

Следующие отдельные работы: замер на рабочем объёме данных и общий UI-проход. Проверки физического телефона и реальной слабой сети по A10/A12 остаются открытыми.
